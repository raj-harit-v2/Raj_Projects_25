# STAGED QUERIES (Building Partial Results)
For complex queries, break them into stages:
- Stage 1: Search for initial information in documents
- Stage 2: Search for additional related information in documents
- Stage 3: Combine and synthesize final answer from document results

**IMPORTANT**: For document queries, ONLY search documents. If information is not found, return "FINAL_ANSWER: Information not found in stored documents" - DO NOT fall back to web search.

**CRITICAL: ANSWER FORMAT**
- DO NOT return raw chunks or long text dumps
- ALWAYS extract key information and provide a CONCISE summary (1-3 sentences)
- Focus on directly answering the user's query
- Example: Instead of returning full chunk text, extract: "Don Tapscott and Anthony Williams argued for open source strategies in clean technologies in their 2010 book MacroWikinomics."

Use `FURTHER_PROCESSING_REQUIRED:` to pass intermediate results to the next stage.

# JOIN STRATEGY FOR RELATIONSHIP QUERIES (HIERARCHICAL)
When searching for relationships between multiple entities, use a HIERARCHICAL approach:

1. **FIRST: Combined Query (INNER JOIN semantics)**
   - Query: "entity1 and entity2" or "entity1 entity2 relationship"
   - Filter results to chunks that contain BOTH entities
   - Best for finding direct relationships (most precise)

2. **FALLBACK: Separate Queries + INNER JOIN**
   - Search each entity separately
   - Keep ONLY chunks that contain BOTH entities (intersection)
   - Good when combined query doesn't work but both entities exist

3. **LAST RESORT: FULL OUTER JOIN**
   - Search each entity separately
   - Return ALL chunks from both searches (union)
   - Let LLM synthesize relationship from separate information
   - Use only when no chunks contain both entities together

For simple entity queries (not relationships), use FULL OUTER JOIN:
- Example: "What do you know about Don Tapscott and Anthony Williams?"
- Return ALL chunks from both searches (they may not appear together)

**Staged Query Example (Relationship Search - Documents ONLY - HIERARCHICAL JOIN):**
```python
async def solve():
    # HIERARCHICAL JOIN STRATEGY for relationship queries:
    # 1. FIRST: Combined query (INNER JOIN semantics - finds chunks with both entities)
    # 2. FALLBACK: Separate queries + INNER JOIN (filter to chunks with both)
    # 3. LAST RESORT: FULL OUTER JOIN (all chunks from both searches)
    
    # Stage 1: Search for both entities together (BEST - INNER JOIN semantics)
    result = await mcp.call_tool('search_stored_documents', {{"input": {{"query": "Gensol Go-Auto relationship"}}}})
    chunks = result if isinstance(result, list) else []
    
    # Filter to chunks that actually contain both entities (INNER JOIN)
    chunks_with_both = []
    for chunk in chunks:
        chunk_lower = str(chunk).lower()
        if "gensol" in chunk_lower and "go-auto" in chunk_lower:
            chunks_with_both.append(chunk)
    
    # If combined query found chunks with both entities, use them
    if chunks_with_both:
        combined = "\n\n".join([str(chunk) for chunk in chunks_with_both])
        return f"FURTHER_PROCESSING_REQUIRED: Found relationship info: {{combined}}"
    
    # Stage 2: If combined query didn't find both together, try separate searches + INNER JOIN
    result1 = await mcp.call_tool('search_stored_documents', {{"input": {{"query": "Gensol"}}}})
    result2 = await mcp.call_tool('search_stored_documents', {{"input": {{"query": "Go-Auto"}}}})
    chunks1 = result1 if isinstance(result1, list) else []
    chunks2 = result2 if isinstance(result2, list) else []
    
    # INNER JOIN: Find chunks that appear in BOTH result sets (contain both entities)
    chunks_with_both_inner = []
    for chunk1 in chunks1:
        chunk1_str = str(chunk1)
        chunk1_lower = chunk1_str.lower()
        # Check if this chunk also appears in chunks2 (contains both entities)
        for chunk2 in chunks2:
            chunk2_str = str(chunk2)
            # If chunks are the same or chunk1 contains both entities
            if chunk1_str == chunk2_str or ("go-auto" in chunk1_lower and "gensol" in chunk1_lower):
                if chunk1 not in chunks_with_both_inner:
                    chunks_with_both_inner.append(chunk1)
                break
    
    # If INNER JOIN found chunks with both, use them
    if chunks_with_both_inner:
        combined = "\n\n".join([str(chunk) for chunk in chunks_with_both_inner])
        return f"FURTHER_PROCESSING_REQUIRED: Found relationship info: {{combined}}"
    
    # Stage 3: LAST RESORT - FULL OUTER JOIN (all chunks from both searches)
    # Use when no chunks contain both entities together - let LLM synthesize relationship
    info1 = "\n\n".join([str(c) for c in chunks1]) if chunks1 else "No information found"
    info2 = "\n\n".join([str(c) for c in chunks2]) if chunks2 else "No information found"
    combined = f"Gensol info:\n{{info1}}\n\nGo-Auto info:\n{{info2}}"
    return f"FURTHER_PROCESSING_REQUIRED: {{combined}}"
```

**Staged Query Example (Payment Extraction with Indian Currency):**
```python
import re

async def solve():
    """
    Finds the amount Anmol Singh paid for his DLF apartment via Capbridge.
    Handles Indian currency units: crore, lakh, thousand
    IMPORTANT: Always return in original currency format - DO NOT convert to USD
    """
    # Stage 1: Search for payment information in documents
    result = await mcp.call_tool('search_stored_documents', {{"input": {{"query": "Anmol Singh DLF apartment Capbridge payment"}}}})
    chunks = result if isinstance(result, list) else []
    
    if chunks:
        combined_text = " ".join([str(chunk) for chunk in chunks])
        
        # Stage 2: Extract amount with currency unit - prioritize specific context
        # Look for "Capbridge paid Rs. X crore to DLF" pattern first (most specific)
        # Then fallback to other patterns
        
        patterns = [
            # Pattern 1: Most specific - "Capbridge paid Rs. X crore to DLF" (for apartment payment)
            r"Capbridge\s+paid\s+(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)\s+to\s+DLF",
            # Pattern 2: "Capbridge...Rs. X crore...DLF...apartment"
            r"Capbridge.*?(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand).*?DLF.*?apartment",
            # Pattern 3: "Rs. X crore...Capbridge...DLF"
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand).*?Capbridge.*?DLF",
            # Pattern 4: General - "Rs. X crore" near "Capbridge" or "DLF" or "apartment"
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)\s*(?:.*?(?:Capbridge|DLF|apartment))",
            # Pattern 5: Fallback - any "Rs. X crore"
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)",
        ]
        
        amount_match = None
        for pattern in patterns:
            amount_match = re.search(pattern, combined_text, re.IGNORECASE)
            if amount_match:
                break
        
        if amount_match:
            amount_str = amount_match.group(1).replace(",", "")  # Remove commas
            amount = float(amount_str)
            unit = amount_match.group(2).lower() if len(amount_match.groups()) > 1 and amount_match.group(2) else ""
            
            # Format answer in original currency format - DO NOT convert
            if unit == "crore":
                return f"FINAL_ANSWER: Anmol Singh paid Rs. {{amount}} crore for his DLF apartment via Capbridge."
            elif unit == "lakh":
                return f"FINAL_ANSWER: Anmol Singh paid Rs. {{amount}} lakh for his DLF apartment via Capbridge."
            elif unit == "thousand":
                return f"FINAL_ANSWER: Anmol Singh paid Rs. {{amount}} thousand for his DLF apartment via Capbridge."
            else:
                return f"FINAL_ANSWER: Anmol Singh paid Rs. {{amount}} for his DLF apartment via Capbridge."
        else:
            return f"FURTHER_PROCESSING_REQUIRED: Payment information found: {{combined_text[:500]}}"
    
    return "FINAL_ANSWER: No payment information found in stored documents"
```

import re
import math

async def solve():
    """
    Calculates the log value of the amount Anmol Singh paid.
    Converts currency units to full number format for calculation, but shows original format in answer.
    IMPORTANT: DO NOT convert between currencies (INR to USD) - keep original currency
    """

    result = await mcp.call_tool('search_stored_documents', {{"input": {{"query": "Anmol Singh DLF apartment Capbridge payment"}}}})
    chunks = result if isinstance(result, list) else []

        patterns = [
            # Pattern 1: Most specific - "Capbridge paid Rs. X crore to DLF"
            r"Capbridge\s+paid\s+(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)\s+to\s+DLF",
            # Pattern 2: "Capbridge...Rs. X crore...DLF...apartment"

            # Pattern 3: "Rs. X crore...Capbridge...DLF"
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand).*?Capbridge.*?DLF",
            # Pattern 4: General - "Rs. X crore" near context
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)\s*(?:.*?(?:Capbridge|DLF|apartment))",
            # Pattern 5: Fallback
            r"(?:Rs\.?|₹|INR)\s+(\d+(?:,\d{{3}})*(?:\.\d+)?)\s*(crore|lakh|thousand)",
        ]
        
        amount_match = None
        for pattern in patterns:
            amount_match = re.search(pattern, combined_text, re.IGNORECASE)
            if amount_match:
                break
        
        if amount_match:
            amount_str = amount_match.group(1).replace(",", "")
            amount = float(amount_str)
            unit = amount_match.group(2).lower() if len(amount_match.groups()) > 1 and amount_match.group(2) else ""
            
            # Stage 3: Convert to full number format for calculation
            # Indian currency: 1 crore = 10,000,000 | 1 lakh = 100,000 | 1 thousand = 1,000
            # USD: 1 million = 1,000,000 | 1 billion = 1,000,000,000
            if unit == "crore":
                full_amount = amount * 10000000  # 1 crore = 10 million
                original_format = f"Rs. {{amount}} crore"
                full_format = f"Rs. {{full_amount:,.0f}}"
            elif unit == "lakh":
                full_amount = amount * 100000  # 1 lakh = 100,000
                original_format = f"Rs. {{amount}} lakh"
                full_format = f"Rs. {{full_amount:,.0f}}"
            elif unit == "thousand":
                full_amount = amount * 1000
                original_format = f"Rs. {{amount}} thousand"
                full_format = f"Rs. {{full_amount:,.0f}}"
            elif unit == "million":
                full_amount = amount * 1000000
                original_format = f"USD {{amount}} million"
                full_format = f"USD {{full_amount:,.0f}}"
            elif unit == "billion":
                full_amount = amount * 1000000000
                original_format = f"USD {{amount}} billion"
                full_format = f"USD {{full_amount:,.0f}}"
            else:
                full_amount = amount
                original_format = f"Rs. {{amount}}"
                full_format = f"Rs. {{full_amount:,.0f}}"
            
            # Stage 4: Calculate log (use full number format)
            log_value = math.log10(full_amount)
            
            # Return in original currency format - DO NOT convert to USD
            return f"FINAL_ANSWER: {{original_format}} ({{full_format}}). Log value (base 10): {{log_value:.6f}}"
        else:
            return f"FURTHER_PROCESSING_REQUIRED: Payment information found: {{combined_text[:500]}}"
    
    return "FINAL_ANSWER: No payment information found in stored documents"
